# Audit findings — 2026-05-20 (v0.5.1)

Three parallel agents reviewed the codebase against:
- **Multi-tenant correctness + Electron security**
- **Briefing + CLAUDE.md compliance**
- **Performance + dead code**

Findings below. Tier 1 was patched in v0.5.2; **Tier 2 patched in v0.6.0**; **Tier 3 safe subset patched in v0.7.0** (Move/Brush tools, Persistent Import Queue, and `products.list` precomputed columns remain deferred — see notes below).

## TIER 2 — Patched in v0.6.0

### Polish + UX consistency
- All `window.confirm` destructive prompts → shared Modal with `closeOnBackdrop={false}` (Company/Brand/Product/Category/Profile/AI delete, Settings data-folder change)
- Brands page card grid missing pagination (violates CLAUDE.md §10 at >50 brands)
- AI Studio queue list slices to 20 with no pagination
- Emoji in Dashboard banner and Support page copy violate CLAUDE.md §18
- Export Center "Partial" badge missing unprocessed-image count
- Export Center ProfilePreview shows placeholder SVG, not a real processed product image
- Image Workspace breadcrumb chip shows SKU only; briefing wants `SKU · Product Name`
- Settings: built-in marketplace presets aren't surfaced (only custom editor)

### Perf — small wins
- N+1 queries in `companies.list`, `brands.list`, `categories.list`, `dashboard.recentProducts` (one subquery per row)
- Missing indexes:
  - `product_images.is_processed`
  - `products.updated_at`
  - `ai_gallery(product_id, created_at)`
  - `ai_tasks(company_id, created_at)`
- Synchronous `fs.readFileSync` in `workspace:processImage`, AI providers' `uploadSource`, queue runner writes (use `fs.promises.*`)
- `addToast` setTimeout never cleared on early dismiss
- AI queue runner does full scan every 2s even when idle

### Defensive
- `settings:changeDataFolder` will `cpSync` from any source path
- `app:openExternal` URL validation could use `new URL(target)` first
- CSP includes `http://localhost:*` in `connect-src` in production HTML — should be dev-only
- `main/index.js` `sandbox: false` — document why, or turn it back on
- `processingPipeline.processedDirForSku(sku)` joins `sku` directly; SKU with `..` could escape — slugify first

## TIER 3 — Status

### Patched in v0.7.0

- ✅ `bulkUpsert` — now pre-fetches existing SKUs in one chunked SELECT instead of per-row getBySku.
- ✅ Table/Grid row memoization — `React.memo` + stable `useCallback` handlers.
- ✅ AI queue runner: early-exit when idle (landed in v0.6.0) + start-task path now rolls back the inflight slot if the DB write throws.
- ✅ Dead code sweep — removed `removeAssetIfOrphaned`, 3× `countByCompany`, 7× row-mapper exports, 1× unused `useMemo` import (AIStudio still uses it).
- ✅ `parseJson` hoisted to `main/db/_util.js`.
- ✅ `slugify` consolidated into `main/util/slug.js`; imageManager / exportRunner / processingPipeline / AI queue runner all use it.

### Deferred — real features, not fixes

- **Move (pan) + Brush (edge touch-up) tools** — both need a real canvas-editor library (fabric.js / Konva). Tracked as a future minor release.
- **Persistent Import Queue** with sidebar badge for unmatched auto-match files (briefing §1) — needs UX design + persistence schema.
- **`products.list` precomputed columns** — would require maintaining `image_count` + `main_image_path` columns on every image add/remove/setMain via triggers or transaction wrappers. High invariant-risk, low marginal perf win after the Tier 2 N+1 fixes. Park for now.

## Known intentional deviations (not bugs)

- ProductForm is a slide-in side panel, not a Modal (matches briefing §1's "right panel" intent; documented in v0.3.0 changelog).
- Editors keep an explicit Save button rather than auto-save with status indicator (deliberate for explicit confirmation; deviates from CLAUDE.md §6).
- Brand and Category filters are multi-select (briefing); Status and Process Status are single-select (deliberate simplification).
- Export Center queue lists all company products with checkboxes, not a separately-maintained "+ Add products" queue.
- `imageManager.js` uses clean `<slug>.<ext>` filenames with hash stored in DB (intentional v0.5.0 divergence from CLAUDE.md §9's `slug-<hash10>.ext` pattern — content-addressed dedup preserved via the DB column).
